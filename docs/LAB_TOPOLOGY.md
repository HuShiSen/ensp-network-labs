# 建议拓扑与地址规划

一套能覆盖本仓库全部技术点、又不至于吃满内存的拓扑（约 12 台设备，16G 内存机器可跑）。

## 1. 拓扑结构

```
                        ┌─────────────┐
                        │  AR-EDGE    │  运营商侧出口（eBGP AS 200）
                        └──────┬──────┘
                               │ 10.10.0.0/30
                      ┌────────┴────────┐
                      │  FW1  (USG6000V)│  安全区域：trust / untrust / dmz / ha
                      └────────┬────────┘
                               │ 192.168.100.0/24
                    ┌──────────┴───────────┐
                    │  LSW-CORE-A (S5700)  │  VRRP Master / STP 根桥
                    └───┬──────────┬───────┘
              Eth-Trunk │          │ VRRP 心跳与互联
                    ┌───┴──────────┴───────┐
                    │  LSW-CORE-B (S5700)  │  VRRP Backup / STP 备根
                    └───┬──────────┬───────┘
        Trunk(VLAN10/20/30)│        │ Trunk
                 ┌─────────┴──┐  ┌──┴─────────┐
                 │ LSW-ACC-1  │  │ LSW-ACC-2  │  接入层（接 PC / 服务器）
                 └────────────┘  └────────────┘

  分支机构 / 灾备侧（IP-VPN 隧道两端）
     R-BRANCH (AR2240) ──GRE Tunnel0/0/0──> AR-EDGE
```

- 双核心用 **Eth-Trunk** 互联（两根线，验证聚合与断链）
- 双核心对下提供 **VRRP 虚拟网关**（VLAN 10/20/30 各一个 VRID）
- **FW1** 既做域间策略与 NAT，也可对开第二台 USG6000V 演练 **HRP 双机热备**（本仓库 09 目录给了主备两份配置）
- 需要 **端口镜像** 时，把观察口接到一台装有抓包工具的 PC

## 2. 地址与 VLAN 规划

| 网段 | 用途 | 网关 | 备注 |
|---|---|---|---|
| 10.10.0.0/30 | FW1 ↔ AR-EDGE 互联网段 | — | 只有两个可用地址 |
| 202.1.1.0/24 | 模拟公网（AR-EDGE 的 Loopback / 对端） | 202.1.1.1 | 供 NAT 与公网可达性测试 |
| 192.168.100.0/24 | 服务器区 | 192.168.100.1 | FW1 的 trust 侧 |
| 192.168.50.0/24 | 外联/发布区（DMZ） | 192.168.50.1 | 目的 NAT 发布用 |
| 192.168.10.0/24 | VLAN 10 办公 | 192.168.10.254（VRRP 虚 IP） | VRID 10，Master 优先级 120 |
| 192.168.20.0/24 | VLAN 20 视频 | 192.168.20.254（VRID 20） | 优先级 120 / 100 |
| 192.168.30.0/24 | VLAN 30 柜台业务 | 192.168.30.254（VRID 30） | 优先级 120 / 100 |
| 10.10.30.0/30 | HRP 心跳专用 | — | **心跳口必须加入安全区域**（见 PITFALLS #3） |

## 3. 路由与 AS 规划

| 域 | 协议 | 说明 |
|---|---|---|
| 园区核心 | OSPF 区域 0 | LSW-CORE-A/B、FW1、AR-EDGE 内网口 |
| 分支/二级域 | OSPF 区域 10 | 由 LSW-CORE-A 做 ABR（`abr-summary` 可汇总） |
| 对外互联 | eBGP | 本域 AS 100 ↔ 运营商 AS 200，仅宣告汇总网段 |
| 内网互通 | OSPF ↔ BGP 双向重分发 | 用 route-policy / filter-policy 控制，避免环路 |

## 4. 内存与性能建议（eNSP 实战）

- 只跑本仓库全部技术点，**建议不超过 12~14 台设备**；USG6000V 最吃内存，一台约等于 2~3 台交换机。
- 需要更多设备时**分组启动**：先起核心与防火墙 → 验证通过 → 停掉接入层 → 再起分支侧。
- 交换机下配置较多时建议用控制台 TCP 端口脚本下发（见 `scripts/`），比手工粘帖稳。
- eNSP 里**不要用命令行或 VBoxManage 直接开关虚拟机**：这样拉起来的设备，eNSP 控制台会接不上（回显只有 `#`），必须由 eNSP 图形界面右键启动/停止。

## 5. 验收顺序建议

```
① 基础连通（VLAN/Trunk + 静态/直连）→ ② 二层优化（RSTP / Eth-Trunk / 镜像）
→ ③ 三层路由（OSPF 多区域 → BGP → 重分发）→ ④ 网关冗余（VRRP）
→ ⑤ 安全策略与 NAT（域间策略 / 源 NAT / 目的 NAT）
→ ⑥ 高可用（HRP 双机热备 + 切换实测）→ ⑦ 专线（GRE 隧道）
```

每步都回读验证后再进入下一步——一次性下发全部配置、最后统一排错，是最费时间的做法。

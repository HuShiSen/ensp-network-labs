# 规划与命名约定

多设备实验最容易乱的不是配置本身，而是**口径不统一**：同一个 VLAN 在两台设备上 ID 不同、接口描述缺失、地址随手写。下面这套约定建议照抄，配置就不容易错。

## 1. 设备命名

| 角色 | 命名 | 示例 |
|---|---|---|
| 核心交换机 | `LSW-CORE-A/B` | 主/备双核心 |
| 接入交换机 | `LSW-ACC-1/2` | 接入层 |
| 出口路由器 | `AR-EDGE` | 互联网出口 |
| 分支路由器 | `AR-BRANCH` | 分支/灾备侧 |
| 防火墙 | `FW1/FW2` | 主/备（HRP 对） |

命名统一用 `-` 连接，禁止出现中文与空格（部分工具对中文设备名处理有差异）。

## 2. 接口与连线描述

每条互联链路**两端都要写 description**，格式：`to-<对端设备>-<对端接口>`。

```
interface GigabitEthernet0/0/1
 description to-LSW-CORE-B-GE0/0/1
```

好处：`display interface description` 一屏就能对出全网的物理连接，排错不必翻拓扑图。

## 3. VLAN 与网段对应（固定映射，全项目通用）

| VLAN | 用途 | 网段 | VRRP VRID | 虚 IP |
|---|---|---|---|---|
| 10 | 办公终端 | 192.168.10.0/24 | 10 | 192.168.10.254 |
| 20 | 视频监控 | 192.168.20.0/24 | 20 | 192.168.20.254 |
| 30 | 柜面业务 | 192.168.30.0/24 | 30 | 192.168.30.254 |
| 100 | 服务器区 | 192.168.100.0/24 | — | — |
| 999 | 设备管理 | 192.168.99.0/24 | — | — |

约定：**VRID = VLAN ID**，虚 IP 固定用 `.254`，物理网关用 `.1/.2`（A/B 两台核心）。这样任何一台设备上一看 VLAN 号就知道网段和网关。

## 4. 地址分配规则

- 互联链路一律 `/30`，两端用 `.1` 与 `.2`
- Loopback0 作为 router-id：`x.x.x.x/32`，建议与设备编号对应（如核心 A 用 10.255.0.1）
- 终端地址从 `.100` 起分配，`.1~.99` 保留给网关、VRRP、预留
- 所有示例都用 RFC1918 私网段，禁止在模板里写真实公网地址

## 5. 设备基础配置模板

见 `templates/`：`switch_base.txt`、`router_base.txt`、`firewall_base.txt`。
统一包含：sysname、时区时钟、STP 模式、管理 VLAN、SSH 登录（生产替换为密钥）、日志时间戳、关闭闲置端口。

## 6. 下发与保存纪律（重要）

1. **先写后读**：一段配置下发完立刻回读校验，不要连着发十几段最后一起排错。
2. **save 要一次写入**：在控制台把 `save` 与确认一起发送（`save\rY\r\r`）。分两次发 `y` 会被吞掉回车，你会看到"像是在保存其实没存"。
3. **落盘判据**：`display saved-configuration | include sysname` 能回出设备名，才算真的存了（`display current-configuration` 只代表运行态）。
4. **批量下发脚本**：见 `scripts/push_config.py`，带命令间延时与回显关键字检查。

## 7. 变更记录

每次改配置在文件头注释里追加一行：`# 2026-09-27 调整 OSPF 开销，修正 Area 10 汇总`。有记录，回退时才知道改过什么。
